# 4.19 work notes: singing accuracy, and a better stem split (started 2026-11-15)

Branch `ccr-4ad1fab2-3crvvw`, from main at 4.18.2 (released 2026-11-15 before this work started; the run and the
release page were checked).

## Part 1: singing accuracy (built)

Decisions and why:
- **The singer's line is followed all the way through** (`vocal-melody.js` `trackVoice`), not one reading per
  syllable: a reading every 10 ms on the stem cut to ~15 kHz, several candidate notes per moment, and the cheapest
  path through them (staying put is free, a jump costs, "no voice" is always a choice).
- **Lead only**: the strongest voice wins; quiet moments (under 7% of the loudest singing within 1.5 s) are skipped;
  a moment counts only when one voice is clearly on top (clarity >= 0.6).
- Dead end 1: preferring "the shortest cycle nearly as strong as the strongest" read two voices a sixth or a fourth
  apart as a low note neither sings (the cycle they share). Fixed twice over: a longer cycle now costs 0.2 per
  octave of length, and a note with a strong shorter cycle that isn't its own octave is never "for sure".
- **Checking** (`sing.js` `checkNotes`): heard clearly -> the recording wins. Not heard -> the chart's note only in
  a line that otherwise agrees with the singer (within 150 cents, any octave; 60% of the line), else blank.
- **Scoring along the line** (`SingJudge.on(i, voice, t)`): within the level's cents of the line now or 40/80 ms
  either side. Holding one note through a slide misses; copying it hits.
- A word whose line stays within 0.7 semitone is kept as a plain bar (vibrato is evened out first), so most of
  the lane looks as before; only real slides, bends and runs are drawn as ribbons.
- The lane's reach still comes from the whole tune once (now counting the lines' ends too), so it never moves.
- Auto-tune gets a run as separate notes (`tuneNotes`).
- The mark: `stagehand.singCheck` (per song, kept for good), shown on the lane's label and Karaoke's cards.
  It only exists after a split song has been sung once (the reading happens then, a few seconds).

Not done / ideas: read the notes right after a split finishes (so the mark shows before the first sing);
use the stem's left/right difference to drop wide backing voices harder; a dedicated lead/backing model (see below).

Engineering notes for whichever is picked:
- Already installed with Demucs: torch 2.8.0 (cu126 for Pascal), einops, pyyaml. Missing: rotary-embedding-torch
  and beartype (small). Mel-RoFormer imports librosa only for the mel band table: vendor that function instead
  (librosa drags in numba, ~100 MB). Avoid the audio-separator package (heavy pins).
- Vendor ZFTurbo's MIT model code (~1,500 lines) plus a ~60-line chunked overlap-add loop.
- GTX 1080 Ti: force full precision (half precision is very slow on that chip); 8-second chunks, batch 1–2.
- Model hosts disappear: pin SHA-256 and keep a second address.
- Stems stay six files in the same format; a new model name means a new folder beside the old one, so songs
  already split keep working and "Split stems again" makes the better one.
- Lead/backing ("karaoke") models exist (aufr33/viperx Mel-RoFormer Karaoke, 913 MB, no licence stated): a later
  step for reading the lead even more surely.
